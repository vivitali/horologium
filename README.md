# Winnipeg Tech Events Scraper & Telegram Sharing Web App

Discovers, aggregates, and shares technology events happening in Winnipeg, Manitoba. Scrapes from multiple sources, posts weekly digests to Telegram, and runs a monthly last-weekend meetup poll with an AI-suggested option.

## Features

### Multi-Source Event Aggregation
- **Meetup.com** — schema.org JSON-LD parsing
- **Eventbrite** — `window.__SERVER_DATA__` SSR JSON, with same-organizer-same-day dedupe

### Telegram Integration
- Weekly events digest posted automatically
- Monthly meetup poll from a **dedicated meetup bot**: opens 11 days before
  the last weekend of the month, closes 3 days before, announces and pins the
  winning slot (needs at least 4 votes, otherwise the month is skipped)
- One poll option is generated by Claude Haiku for Winnipeg and the exact
  dates; if generation fails the poll simply ships without it

### Modern Web UI (local)
- Responsive design with dark mode
- Filter by date range, source, search
- Grouping by Today / This Week / Next Week / Later

### Scheduling
- AWS Lambda + EventBridge runs the jobs on schedule (independent of GitHub
  Actions, so it survives long periods of repo inactivity)
- Two Lambdas in one Go module: `winnipeg-tech-events` (digest + annual
  scrape) and `winnipeg-meetup-bot` (daily tick that decides in code whether
  today is a poll day, a summary day, or nothing)

### Deploy
- Manual: `./deploy/deploy.sh`
- CI: `.github/workflows/deploy.yml`, manual "Run workflow" only (OIDC, no long-lived AWS keys). Merging to `main` does not deploy.

## Quick Start

### Prerequisites
- Go 1.24+
- AWS CLI v2 (for deployment) configured via `aws login` or `aws configure sso`
- Telegram bot token + chat ID

### Run locally

```bash
go mod tidy

# Web UI on http://localhost:8080
go run ./cmd/server

# Trigger an events digest manually (test mode, no Telegram send):
TEST_MODE=true \
TELEGRAM_BOT_TOKEN=xxx TELEGRAM_CHAT_ID=yyy \
go run ./cmd/cli -action=events

# Simulate a meetup-bot tick for a given day (state in a local file, nothing sent):
TEST_MODE=true \
TELEGRAM_MEETUP_BOT_TOKEN=xxx TELEGRAM_MEETUP_CHAT_ID=yyy ANTHROPIC_API_KEY=sk-ant-... \
go run ./cmd/cli -action=meetup -date=2026-10-20 -out=/tmp/meetup-state.json
```

### Deploy to AWS Lambda

The Lambda is invoked on a schedule by AWS EventBridge — no GitHub Actions, no
60-day inactivity timeout. Three schedules ship out of the box:

- `winnipeg-events-weekly` — Mondays at 14:00 UTC (9 AM CST)
- `winnipeg-annual-scrape-monthly` — 1st of each month at 13:00 UTC
- `winnipeg-meetup-daily` — every day at 14:00 UTC; the meetup bot acts only
  on the poll day (last Saturday − 11) and the summary day (last Saturday − 3)

```bash
# 1. Configure AWS credentials once
aws login                      # or: aws configure sso

# 2. Put your secrets in deploy/.env (file is gitignored)
cat > deploy/.env <<'EOF'
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
# Meetup bot (separate bot, same group, admin with pin rights)
TELEGRAM_MEETUP_BOT_TOKEN=...
TELEGRAM_MEETUP_CHAT_ID=...
ANTHROPIC_API_KEY=...
EOF

# 3. One-time: SSM policy + parameters (needs IAM rights), then deploy
./deploy/bootstrap.sh
./deploy/deploy.sh

# 4. Smoke test
aws lambda invoke --function-name winnipeg-tech-events \
    --payload '{"action":"events"}' \
    --cli-binary-format raw-in-base64-out out.json && cat out.json

# 5. Tail logs
aws logs tail /aws/lambda/winnipeg-tech-events --follow
```

| Env var | Default | Purpose |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | Bot that posts the events digest |
| `TELEGRAM_CHAT_ID` | — | Chat that receives the events digest |
| `TELEGRAM_MEETUP_BOT_TOKEN` | — | Dedicated meetup bot (must be the bot that sent the poll; `stopPoll` only works on its own polls) |
| `TELEGRAM_MEETUP_CHAT_ID` | — | Chat that receives the meetup poll and summary |
| `ANTHROPIC_API_KEY` | — | Generates the AI poll option (`claude-haiku-4-5`) |
| `MEETUP_SSM_PARAM` | `/winnipeg-tech-events/meetup-state` | SSM parameter holding the meetup bot's monthly state |
| `CITY` | `Winnipeg` | City passed to scrapers |
| `CATEGORIES` | `tech` | Category passed to scrapers |
| `PERIOD_DAYS` | `30` | How many days ahead to scrape |
| `TEST_MODE` | `false` | When `true`, build the message / decision but send nothing and write no state |
| `PORT` | `8080` | Web UI server port (local only) |

### Telegram Bot Setup

You need one bot + chat ID for the weekly events digest and a **second,
dedicated** bot for the monthly meetup poll. The two Lambdas never share a
token: the meetup bot has to own its poll so it can close it later.

#### 1. Create the bot

1. In Telegram, open a chat with [@BotFather](https://t.me/botfather).
2. Send `/newbot` and follow the prompts. Pick:
   - A **name** (display, e.g. `Winnipeg Tech Events`)
   - A **username** ending in `bot` (e.g. `winnipeg_tech_events_bot`)
3. BotFather replies with a token like `8123456789:AAH...`. **This is `TELEGRAM_BOT_TOKEN`.** Save it.
4. (Optional) Send `/setdescription`, `/setabouttext`, `/setuserpic` to fill out the bot profile.

#### 2. Get the chat ID

For a group chat (recommended):

1. Add the bot to the target group as a member.
2. In Telegram, send any message in that group (e.g. `hi`).
3. Open the following URL in a browser, replacing `<TOKEN>`:
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
4. Find the most recent update's `message.chat.id`. For groups this is a
   negative integer like `-1001234567890`. **This is `TELEGRAM_CHAT_ID`.**

For your own DM with the bot, click `/start` first, then the chat ID will be
your positive user ID (e.g. `123456789`).

#### 3. Meetup bot

1. Repeat step 1 with a new BotFather `/newbot` → `TELEGRAM_MEETUP_BOT_TOKEN`.
2. Add that bot to the same group → `TELEGRAM_MEETUP_CHAT_ID` (same value as
   `TELEGRAM_CHAT_ID` when it is the same group).
3. Promote it to **admin with "Pin messages"** so it can pin the monthly
   summary. Without that right the summary still posts; only the pin is
   skipped (logged, not fatal).

## Deploy via GitHub Actions

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) auto-deploys
when you run it manually (it never fires on merge). It uses **OIDC** — no long-lived
AWS keys stored in GitHub.

### One-time AWS setup

Run [`deploy/setup-gha.sh`](deploy/setup-gha.sh) — it creates the GitHub OIDC
provider, the deploy role with a trust policy scoped to your repo, and an
inline policy granting Lambda / EventBridge / IAM / CloudWatch Logs access.
Idempotent — safe to re-run.

```bash
aws login                              # or: aws configure sso
./deploy/setup-gha.sh                  # infers repo from "origin"
# or: REPO=owner/name ./deploy/setup-gha.sh
```

The script prints the `AWS_ACCOUNT_ID` value you need to put into GitHub
Secrets, and the role ARN the workflow assumes.

What it creates (under the hood):
- IAM OIDC provider for `token.actions.githubusercontent.com`
- IAM role `github-deploy-winnipeg-tech-events` with a trust policy locked to
  `repo:<owner>/<repo>:ref:refs/heads/main`
- Inline policy `deploy-permissions` with `lambda:*`, `events:*`, the IAM
  actions `deploy.sh` needs (`GetRole`/`CreateRole`/`AttachRolePolicy`/`PassRole`),
  and CloudWatch Logs retention setup

### One-time GitHub setup

In the repo on github.com: **Settings → Secrets and variables → Actions**.

**Secrets** (encrypted):

| Name | Value |
|---|---|
| `AWS_ACCOUNT_ID` | Your 12-digit AWS account id |
| `TELEGRAM_BOT_TOKEN` | From BotFather |
| `TELEGRAM_CHAT_ID` | From `getUpdates` |
| `TELEGRAM_MEETUP_BOT_TOKEN` | Meetup bot from BotFather |
| `TELEGRAM_MEETUP_CHAT_ID` | Group the meetup bot posts to |
| `ANTHROPIC_API_KEY` | Anthropic API key for the AI poll option |

**Variables** (plain text):

| Name | Default if unset | Purpose |
|---|---|---|
| `CITY` | `Winnipeg` | Scrape target |
| `CATEGORIES` | `tech` | Scrape category |
| `PERIOD_DAYS` | `30` | Days ahead to include |
| `TEST_MODE` | `false` | Build digest but don't send |

### Trigger a deploy

- **Manual**: GitHub repo → **Actions** → **Deploy Lambdas** → **Run workflow** (on `main`).

The workflow ends with a smoke-test invocation of the meetup bot on a past
date (guaranteed no-op) and prints the JSON result. It does not invoke the
events digest, so a deploy never posts to the group.

## Architecture

```
EventBridge (weekly Mon 14:00 UTC)  ─┐
EventBridge (monthly 1st 13:00 UTC) ─┴─▶ Lambda winnipeg-tech-events (Go, provided.al2023)
                                           ├─▶ scrape Meetup / Eventbrite / Luma
                                           ├─▶ SSM /winnipeg-tech-events/annual-events
                                           └─▶ Telegram Bot API (weekly digest)

EventBridge (daily 14:00 UTC) ─────────▶ Lambda winnipeg-meetup-bot (Go, provided.al2023)
                                           ├─▶ SSM /winnipeg-tech-events/meetup-state
                                           ├─▶ Anthropic API (claude-haiku-4-5, poll day only)
                                           └─▶ Telegram Bot API: sendPoll / stopPoll / sendMessage / pinChatMessage
```

### Meetup bot flow

All dates are civil dates in `America/Winnipeg`; S is the last Saturday of
the month (Fri = S−1, Sun = S+1).

| Day | Action |
|---|---|
| S−11 | Send one multi-select, non-anonymous poll naming the three dates: Fri ~18:30 кава/пиво, Sat and Sun at ~12:00 кава or ~18:30 кава/пиво, a 🤖 AI idea (own slot + activity), ❌ can't this month |
| S−3 | `stopPoll`, pick the option with the most votes (❌ excluded, ties → earliest). ≥4 votes: post + pin the winner. Otherwise post "skipping this month" |

A missed tick self-heals the next day; running a tick twice is a no-op
because the phase is stored in SSM. There is no webhook and no inbound HTTP.

```
  timeutil/     # Date grouping helpers
  models/       # Event struct

  scraping/     # Multi-source scraping service
  meetup/       # Meetup scraper (schema.org JSON-LD)
  eventbrite/   # Eventbrite scraper (window.__SERVER_DATA__)

  aggregator/   # Result merging & deduping
deploy/
  deploy.sh     # Idempotent AWS deploy of both Lambdas + EventBridge rules
  bootstrap.sh  # One-time IAM/SSM setup (operator with IAM rights)

web/            # Local web UI assets
```
